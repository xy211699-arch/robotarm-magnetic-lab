# TASK-010 CNN+GRU 视觉依赖性验证设计

## 文档地位与目标

本文是经用户确认的 TASK-010 视觉依赖性验证架构设计。它回答两个可证伪问题：冻结
ResNet18 加 GRU 的策略是否比只使用上一实际动作和循环记忆的策略取得更高覆盖效率，以及
已训练策略是否依赖与当前胶囊物理状态正确对应的实时视觉。本文不把“CNN+GRU 覆盖率较高”
直接解释为“策略使用了视觉”，也不以削弱随机策略制造性能差距。

本文只增加视觉信息消融、推理期视觉干预、配对评估和人工启动监督入口。胃模型、覆盖定义、
六模式动作、奖励、PPO、十二环境并行、相机、图像预处理和 Critic 特权边界保持不变。VLM、
提示相似度、跨胃几何、图像增强和新动力学随机化不在本任务范围内。

## 数据划分与使用时机

冻结位姿库继续分为训练 1000 条、验证 100 条和测试 100 条，三部分互不重叠。训练进程只能
使用 training split。当前视觉依赖性开发与方法冻结只使用现有配置中的 20 个固定 validation
位姿及其一个既有固定扰动种子，不新增扰动分布，也不读取 test split。

现有 20 个 validation 位姿的顺序以冻结配置中的 `validation.pose_ids` 为准。B0、B1、I1 和
I2 必须使用相同位姿、相同单扰动、相同 120 秒预算和相同确定性动作规则。validation 结果用于
选择检查点、检查视觉依赖性和冻结分析程序，不写成最终 test 结果。

最终 test 只在 VLM 选型、提示、四组核心模型、检查点规则和本设计的统计程序全部冻结后统一
执行。届时从 100 个 test 位姿中生成一个不可变的 20 位姿清单；若仓库已有正式测试清单则直接
使用，若尚无清单，则计算固定字符串 `task010-visual-dependence-v1|<pose_id>` 的 SHA-256，按摘要
升序取前 20 个，并在读取任何 test 覆盖结果前提交清单及清单 SHA-256。该规则可复现、与性能
无关且不能人工挑选位姿。每个 test 位姿同样只使用清单中一个固定扰动种子。最终 test 不参与
任何模型选择或方案修改。

## 实验条件

### B0：正常 CNN+GRU

B0 使用现有冻结 ResNet18、512 到 256 视觉投影、上一动作投影、融合层、单层 GRU 和策略头。
Actor 在推理时读取当前 10 Hz RGB、上一实际动作和自身 GRU 隐状态。Critic 只在训练期读取
特权状态，且不与 Actor 共享可训练表示。

B0 使用已经完成的正式训练种子 `991001`、`991002` 和 `991003`。update 750 是视觉依赖性
主比较检查点，update 1000 只用于预先声明的训练稳定性敏感性分析。不得根据 B1、I1、I2 或
test 结果为不同种子重新挑选检查点。

### B1：Blind-GRU

B1 保留与 B0 相同的模型对象、可训练层、参数维度、初始化、Critic、PPO、奖励、训练位姿、
并行数、rollout、更新数和日志。每一帧仍完成与 B0 相同的 RGB 采集、预处理和冻结 ResNet18
前向，但在 512 维视觉特征进入可训练视觉投影前，将其替换为固定全零向量。这样 B1 的 Actor
只能使用上一实际动作和 GRU 记忆，且 B0 与 B1 的可训练参数清单完全一致。

B1 使用条件隔离后的 `991001`、`991002` 和 `991003` 三个正式种子，训练至 update 1000，
保存 250、500、750 和 1000 检查点。B1 不单独调节学习率、熵系数、网络维度、奖励或训练
预算。论文结论因此限定为“相同训练协议下视觉信息的增量价值”，不声称 B1 是全局最优无视觉
算法。

### I1：跨回合视觉错配

I1 不训练新模型，而是在 B0 update 750 推理时，将目标回合的 512 维视觉特征替换为另一个
validation 位姿的离线供体特征序列。供体必须由同一个 B0 检查点在正常视觉条件下生成，保留
真实胃内图像特征的数值分布，同时破坏图像与当前物理状态的对应关系。

供体映射按冻结 validation ID 顺序循环错排：位姿 `i` 接收位姿 `i+1` 的特征，最后一个位姿
接收第一个位姿的特征。任何位姿不得接收自己的序列。目标回合的 GRU 从零初始化，上一动作
必须来自目标胶囊实际执行的动作，环境状态、覆盖计算和动作执行也全部属于目标回合。供体序列
在目标回合开始前离线缓存，目标动作不能改变供体内容。

### I2：首帧冻结

I2 使用 B0 update 750 检查点，并将目标回合 `t=0` 的真实 512 维视觉特征重复输入到整个
120 秒回合。上一实际动作、GRU 更新、物理仿真和覆盖评价保持正常。I2 用于区分初始视觉作用
与持续闭环视觉作用，属于辅助机制实验，不单独决定核心结论。

### R3：描述性环境参照

R3 保留 TASK-009C 已有结果，不新增随机实验，也不参与 B0、B1、I1 和 I2 的正式推断。
如在论文图中展示，必须标注其原始五个位姿样本口径，并明确它只是无学习环境参照。随机策略
不得因性能较高而被修改或人为削弱。

## 训练与评估矩阵

B1 新增三次正式训练，每次运行 1000 次 PPO 更新。validation 主矩阵在 update 750 上评估
B0、B1、I1 和 I2，每个条件包含三个训练种子乘 20 个固定 validation 位姿乘一个固定扰动，
共 60 个完整回合；四个条件共 240 个回合。敏感性矩阵在 update 1000 上只评估 B0 和 B1，
共 120 个回合。

B0 正常 update 750 评估必须重新运行并缓存供体特征，使 B0 与 I1 使用同一版代码、清单和
运行环境。已有 B0 validation 覆盖结果可用于交叉核对，但缺少本设计要求的供体特征与配对清单
时不能代替本次 B0 正常评估。

所有回合固定为 120 秒、1200 个 10 Hz 动作和包含 `C0` 的 1201 个原始覆盖点。模式采用最大
概率动作，非 HOLD 力度使用条件 Beta 分布均值。评估不调用 Critic，也不更新模型、归一化器
或优化器。

## 指标与确认性比较

唯一确认性主指标为 `nAUC_120`。两个确认性效应为

$$
\Delta_{\mathrm{vision}}
=
\operatorname{nAUC}_{120}(B0)
-
\operatorname{nAUC}_{120}(B1)
$$

和

$$
\Delta_{\mathrm{alignment}}
=
\operatorname{nAUC}_{120}(B0)
-
\operatorname{nAUC}_{120}(I1).
$$

次要指标为 `C30`、`C60`、`C120`、达到 80%、90% 和 95% 覆盖率的时间与达标比例、
位姿分布低尾、最长停滞、动作比例和力度分布。未达阈值回合必须保留并报告未达比例，不能从
时间统计中删除。300 秒结果不进入核心比较，因为已有证据显示其天花板效应严重。

轨迹叠加、动作时间线和通过参数随机化检查的显著性图只作辅助解释，不构成视觉依赖性主证据，
也不能用于选择统计回合。

## 统计分析

算法层面的独立单位是训练种子。测试位姿和单扰动回合是每个训练策略下的配对重复测量，1201
个时间点是同一回合的纵向记录。论文应报告 `n=3` 个独立训练种子，并另行说明每个种子包含
20 个位姿；不得将 60 个回合或 1201 个时间点写成算法独立样本数。

分析先对每个训练种子计算 20 个配对位姿的条件差异，再报告三个种子的全部差值、均值、标准差
和分层 bootstrap 95% 置信区间。bootstrap 先重采样训练种子，再在种子内部重采样成对位姿。
由于训练种子只有三个，论文必须明确小样本限制，不以单独的 `p < 0.05` 作为通过依据。

只有 `B0-B1` 和 `B0-I1` 属于确认性比较。若报告假设检验，对这两个比较使用 Holm 校正；
其余条件、检查点和指标均标记为次要或探索性。低覆盖回合、困难位姿和正常训练波动不得作为
异常值排除。

## 结论门槛

只有当三个正式种子的 `Delta_vision` 和 `Delta_alignment` 方向均为正、分层 95% 置信区间
均不跨零，并且效应不是由单一位姿独占时，论文才能主张“实时且状态对齐的 RGB 在相同训练
协议下提高覆盖效率，并被策略用于闭环决策”。三个种子的规模仍需在论文局限性中披露。

若 B0 高于 B1 而 I1 不下降，只能说视觉输入与训练后的性能差异相关，不能证明持续在线视觉
反馈。若 I1 下降而 B0 与 B1 相近，只能说 B0 读取视觉，不能说视觉提高覆盖。若两个效应均不
成立，应接受当前环境主要可由动作历史、循环记忆或动力学规律解决，并收缩论文主张。

## 耗时预算

耗时以现有三个 B0 正式种子的 Linux 实测为依据：单种子 update 1000 平均训练约 5 小时
25 分 14 秒，20 位姿验证平均约 11 分 06 秒。三个 B1 训练预计约 16 小时 16 分；四个 update
750 条件预计约 2 小时 13 分；两个 update 1000 敏感性条件预计约 1 小时 07 分。核心 V3
有效计算合计约 19 小时 36 分，计入预检查、供体缓存、阶段切换和工件审计后，为人工运行预留
21 至 23 小时。

最终 test 阶段不重新训练，只重复冻结后的六个评估条件，预计增加约 3 小时 20 分及少量审计
时间。实际 ETA 由监督脚本根据当前 update 和最近吞吐动态更新，不作为实验通过条件。

## 人工启动监督架构

正式 V3 由用户人工启动，Codex 不启动、不等待也不轮询长时间任务。新增入口固定为
`scripts/stomach_coverage/task010_visual_dependence_supervisor.py`，复用现有 TASK-010 正式
种子监督器的脱离终端、原子状态、心跳、错误暂停和人工继续模式。

监督器公开四个命令。`start` 完成预检查后创建唯一运行目录，以独立进程会话启动后台协调器，
打印 `run_id`、绝对运行目录和 PID 后立即退出。`status` 只读输出一次当前进度。`watch` 每
60 秒刷新只读状态，用户中断 `watch` 不影响后台实验。`continue` 只允许在用户检查错误后，
对持久化为 `paused_on_error` 的运行显式恢复。

正式启动接口为：

```bash
python3 scripts/stomach_coverage/task010_visual_dependence_supervisor.py start \
  --config configs/task010/visual_dependence_v1.json
```

状态和观察接口为：

```bash
python3 scripts/stomach_coverage/task010_visual_dependence_supervisor.py status
python3 scripts/stomach_coverage/task010_visual_dependence_supervisor.py watch --interval 60
```

人工检查错误后的恢复接口为：

```bash
python3 scripts/stomach_coverage/task010_visual_dependence_supervisor.py continue \
  --run-dir /absolute/path/to/run
```

## 监督与异常处理

后台协调器每 5 秒原子更新心跳，并检查协调器 PID、当前子进程 PID、退出码、最新训练 update、
评估位姿进度、最近检查点和指标时间。状态输出包含当前条件、种子、update、位姿进度、已运行
时间、动态 ETA、心跳年龄、指标年龄、PID 和错误摘要。

训练稳定运行后五分钟没有新指标时，状态标记 `suspected_stall` 并记录警告；十五分钟没有新
指标时禁止进入后续阶段并要求人工检查。仅凭指标停滞不自动杀死仍存活的训练子进程，避免把
编译、检查点写入或阶段切换误判为故障。PID 消失、僵尸进程、非零退出、CUDA OOM、非有限
指标、配置变化或必需工件缺失会进入 `paused_on_error`。

监督器不自动重试、不跳过失败种子、不更换种子、不降低预算，也不覆盖既有运行目录。外部进程
中断允许从最后有效 rollout 边界恢复；代码、奖励、模型、配置或非有限训练错误修复后，相应
正式种子必须从 update 0 重训。已经完成并通过哈希审计的其他种子和评估阶段可以复用。

## 门禁定义

V0 验证信息隔离和配置一致性，证明 B1 在视觉投影前只收到固定零向量，B0 与 B1 的可训练参数
清单相同，Critic 特权信息不进入 Actor。V1 使用独立冒烟种子验证 B1 前向、反向、日志、检查点
和恢复。V2 在 validation 小样本上验证供体错排、首帧冻结、目标上一动作、1201 点曲线和条件
间唯一变量。

V3 的代码验收只验证人工 `start`、后台脱离、`status`、`watch`、心跳、受控失败、错误暂停和
人工 `continue`，不执行正式三种子。Linux 返回报告必须明确写出“正式 V3 等待用户人工启动”。
用户人工启动后，监督器顺序执行 B1 三种子训练和全部 validation 条件；任一阶段失败立即停止
后续阶段。

V4 在全部阶段结束后从原始工件重新计算指标，生成逐种子摘要、逐位姿配对差异、置信区间、
覆盖曲线、阈值统计和故障清单。只有全部预定工件通过数量、范围、单调性、检查点和配置哈希
审计后，状态才允许写成 `completed`。

## 工件与论文输出

每次运行保存不可变 `manifest.json`、原子 `status.json`、`events.jsonl`、协调器日志、各阶段
独立控制台日志、训练指标、检查点及哈希、供体映射、逐回合记录、每回合 1201 点覆盖曲线、
动作与力度摘要、技术故障记录和最终汇总。原始 RGB 不默认长期保存；供体库保存 512 维特征、
来源位姿、时间索引、检查点哈希和配置哈希。

论文主图显示 B0、B1、I1 和 I2 的 120 秒覆盖曲线，并明确误差带、训练种子数、位姿数和单扰动
口径。主表报告 `nAUC_120`、`C120`、阈值时间与达标比例，以及 `B0-B1` 和 `B0-I1` 的配对
差异和 95% 置信区间。R3 如被展示，只作为不同样本口径的描述性参照。

## 验收完成语义

设计、实施计划、代码、测试和监督入口完成，不等于正式视觉依赖性实验完成。用户尚未执行
`start` 时，状态只能写成“实现完成，正式实验待人工启动”。只有 B1 三个训练种子、所有
validation 条件、敏感性分析和 V4 汇总全部通过审计，才能写成“视觉依赖性 validation 实验
完成”。只有四组核心模型冻结后的统一 test 执行完成，相关数字才能写成论文最终测试结果。
