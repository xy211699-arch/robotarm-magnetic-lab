# 新胃连续 RL 预验证设计规格（冻结合同）

**日期：**2026-10-08  
**依据分支：**`release/new-stomach-magnetic-v1-20261008`  
**基准提交（阅读时核对）：**`1e89c9ccb48545c4513915be94d4c17d9cdebaaa`  
**目标：**仅完成可训练性验证，不启动 A/B/C/D 的正式 1000-update 多种子训练。

## 1. 已确认的研究设计

- 单一新胃模型，暂不开展跨胃泛化、扰动恢复或 sim2real 算法。
- 四组预留为 A=Blind+Single、B=Vision+Single、C=Blind+Chunk、D=Vision+Chunk；均使用 GRU 与连续 9D 输出体系。第一轮正式对比之前先完成预验证门禁。
- 输出动作按**当前新胃执行器源码**定义：机械臂末端 3D 平移相对增量、3D 旋转向量相对增量、Ball 3D 角度相对增量；不是旧版 `v1/v2` 绝对关节偏移接口。
- Single 每 1 秒输出一组 9D；Chunk 每 1 秒输出 4×9D，各子动作执行 0.25 秒，四段都必须实际执行。不得混用发布分支中“4×1s 规划，只执行首 1s”的 preview 语义。
- 物理 240 Hz；RGB/策略决策 1 Hz；C10 面积加权几何覆盖按 10 Hz 更新并用于 PPO 奖励，C1 仅在实际 1 Hz 图像采样边界更新，用于评测，不参与奖励。
- 有效观察距离 70 mm；圆形 FOV 120°，第一交点无遮挡及朝向等有效性条件沿用已经验证的覆盖算法。
- 新胃可达目标采用 `docs/NEW_STOMACH_COVERAGE_TUBE_CALIBRATION.md` 的**完整右侧管道 + Tube B 排除**方案：网格总面 429029，候选排除面 176109，候选目标面 252920；目标面积约 0.040205301 m²（72.25%），排除面积约 0.015438635 m²（27.75%）。不可改动物理碰撞/渲染网格。
- 新胃初始位姿库**已经由用户确定**，但 release 仓库的 `configs/new_stomach_v1/` 中目前仅明确看到 `orientation_v1.json`；须在 Linux 工作目录/外部工件中定位用户已确认的文件、记录 SHA-256、检查对应新胃几何和 split。不得猜路径、重建、拿旧胃库替代。
- 奖励：每 0.1 秒沿用 TASK-010 的四项，1 秒内加总作为一次 PPO 奖励：`100 * ΔC10 + 0.1 * ΔEscape - 0.002 * I_no_progress + 0.2 * I_coverage_resumed`。保留 5 秒窗口及旧状态机作为首个候选，先核验阈值适用于新磁控动力学；不得将 bring-up 环境的 alive/action_rate/joint_velocity 等中性奖励意外混入。
- Actor：Blind 仅使用已实际提交执行、经过安全投影后的动作历史；Vision 加 1 Hz RGB 512D frozen ResNet18；不允许 Actor 获得 capsule ground truth、覆盖真值、障碍距离、reward、pose ID、split 或随机数状态。Critic 的特权输入需保持明确隔离。
- 原计划的正式评测：固定 50 个 test 初始位姿、每个 120 s、Mean/Median/P10/CVaR20；本次预验证不使用 test split 挑模型。

## 2. 执行与安全合同

- 旧 TASK-010（10 Hz、离散模式、直接施力）保持原样；本轮新建独立新胃 RL task ID 和独立实现入口，不覆盖 A 版已冻结行为。
- 原机械臂及 Ball 的物理参数、磁场模型、软关节限位、速度/加速度、停止路径检查、网格碰撞检查和 5 mm 安全余量不允许弱化。
- Single/Chunk 采用统一的每秒相对位移预算、速度/加速度约束；Chunk 四段的规划/执行必须有连续位置、速度和加速度（C2）或采用经证明等效安全的连续轨迹方案。禁止直接将四个原 1s 增量压到四个 0.25s 内。
- 不能为性能修改图像分辨率、FOV、观察距离、覆盖掩码、仿真器物理时间步、磁控保护参数、外部 USD 资产。
- 本任务可对与预验证相关的**新增文件**、新 RL 任务配置与必要适配代码实施 TDD；不得直接覆盖归档控制器、旧 benchmark 和训练数据。若必须改动共享核心或资产才能继续，暂停并回报 `needs_decision`。
- 每个门禁均需完整日志、复现命令、环境版本、提交 SHA、日志/数据的文件位置及哈希；外部大工件留在 Git 外。失败时不得以降低安全精度继续推进。

## 3. 验收终点

1. 新任务在 1 环境可执行 HOLD/Single/Chunk 的全闭环 240 Hz 物理步、1 Hz 真实相机采样、10 Hz 几何覆盖、两种频率 coverage 与四项 reward；数值和时钟一致。
2. 新动作方案满足安全约束且四段 Chunk 全部实际执行，旧版 4s preview 行为完全不变。
3. 连续 GRU-PPO 在代表性 A/D 路径下完成小规模前向、反传、更新、保存恢复，值函数/策略损失有限；不声称覆盖率提升。
4. 逐级测试 1/2/4/8/12 环境可行性，输出故障、显存、计算热点、环境吞吐及完整训练预算外推；无法多环境时报告阻塞，不强行抹掉单环境限制。
5. 最终给出 `complete`、`partial`、`needs_input` 或 `needs_decision`，附逐 Gate 证据与正式训练前仍需决策的事项。

**来源与优先级：**用户在当前会话中锁定的研究约束 > 本规格 > release 分支公开实现现状；发现不可兼容或来源证据不足时停止并报告，不擅自调整研究设计。
