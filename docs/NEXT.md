# 下一阶段任务

## 当前下一步

接收并整理用户本地形成的设计，使其成为团队讨论、实现与验收的版本化依据。目前只有 [暂定方向](PROJECT.md)，本次不继续四组训练、不实现新学习模型、不更改硬件或安全行为；具体模块以后续明确采用的方案为准。

## 本地设计入库

设计按日期主题保存于docs/design/，记录版本、作者、依据、已明确项与待决项，并在本页更新当前采用入口。保存必要文字与附图，排除私有路径、凭据和大工件；本地修改、检查、推送后，团队按同一提交协作，不靠旧聊天状态确定工程边界。

## 需要明确的接口

观测设计须明确图像采集与接收时间、观测年龄、接触值和有效性、机构状态及实际动作历史的映射、单位和时序。技能设计须明确候选方式、参数范围、开始结束、执行结果和退出原因，区分请求、实际执行和取消；这些是方案要回答的问题，不是已冻结字段。

模型设计须解决GRU与Transformer冲突，定义短时预测范围、任务误差、接触事件、信息不足判定和候选代价。执行设计须明确传统控制复用、模式互锁、接管、缓存指令作废，以及仿真实物哪些接口一致、哪些需要适配。

## 团队任务与验收

方案明确后再按真实接口划分仿真执行、传感器标定、多模态数据和效果预测、集成验收等任务，写允许范围、依赖、输入输出与最小验证。不根据材料中的分工擅自指定人员或承诺硬件进度。

第一阶段优先形成可检查的观测、技能执行、反馈最小闭环，具体试验与模型由方案决定。当前没有新的正式训练预算、种子数和对照矩阵，补齐旧四组不再是前置条件。
