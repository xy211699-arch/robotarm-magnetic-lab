## Actor 观测边界与图像预处理

Actor 在部署时只能读取当前 10 Hz RGB、上一实际动作和自身 GRU 隐状态。Actor 不得读取
真实位姿、速度、接触、胃壁法向、累计覆盖、覆盖网格、剩余时间、停滞状态机、位姿 ID、
split 或任何 Critic 特权量。

原始 Actor RGB 保持 `1280 × 720`。圆形视野以图像中心为圆心，直径等于短边 720 像素，
圆外像素为零。预处理先从水平方向居中裁出 `720 × 720` 正方形，再使用抗锯齿缩放得到
`224 × 224`，随后转换到 `[0,1]` 并使用 ResNet18 `IMAGENET1K_V1` 对应的 ImageNet
均值和标准差归一化。该流程不拉伸圆形视野，也不改变相机内参或覆盖相机。

本任务不新增随机裁剪、翻转、旋转、透视、亮度、对比度、色调、模糊或噪声增强，也不新增
光照、纹理、材质、摩擦或控制传递随机化。实测增强只能在开发种子返回后进入独立决策门禁；
若启用任何增强或随机化，必须从头重跑开发种子，并在后续所有核心模型组中使用完全相同的
配置。

## Actor 网络

视觉编码器使用 torchvision ResNet18 `IMAGENET1K_V1` 预训练权重。分类头移除后，每帧
输出 512 维视觉特征。ResNet18 全部参数冻结，不进入优化器，训练时始终保持推理模式，所有
BatchNorm 统计量固定。实现应在采样时保存 512 维特征，而不是在 rollout 中保存原始 RGB
或为同一帧重复执行 ResNet18 反向传播。

512 维视觉特征进入可训练的 `512 → 256` 视觉投影层，随后使用 LayerNorm 和 SiLU。上一
实际动作编码为 7 维，其中模式使用 6 维 one-hot，力度使用 1 维标量；上一动作为 HOLD 时
力度固定为零。该向量经可训练的 `7 → 32` 线性层和 SiLU 得到动作特征。

256 维视觉特征与 32 维动作特征拼接为 288 维，经 `288 → 256` 线性层、LayerNorm 和 SiLU
得到 GRU 输入。
时序模块使用单层、单向 GRU，输入维度 256，隐藏维度 256。每个真实环境 reset 只清空对应
环境的隐状态；64 步 rollout 边界仅截断梯度，隐状态继续传递，不得把 rollout 边界误当成
环境 reset。

Actor 的离散头输出六个模式 logits。五个非 HOLD 模式各自拥有一个条件 Beta 力度分布，
因此力度头输出十个原始参数。每个浓度参数按

$$
c = 1 + \operatorname{softplus}(u)
$$

转换，初始化使五个分布接近 `Beta(2,2)`。采样到 HOLD 时令 `alpha=0`，并从联合对数概率和
条件 Beta 熵中屏蔽 HOLD 力度项。联合对数概率固定为

$$
\log \pi(a_t\mid o_t)
= \log \pi_m(m_t\mid o_t)
+ \mathbb{1}[m_t\ne \mathrm{HOLD}]\log \pi_\alpha(\alpha_t\mid m_t,o_t).
$$

确定性验证时，模式取最大概率类别，非 HOLD 力度取相应 Beta 分布均值，HOLD 力度仍为零。

## Asymmetric Critic

Critic 只用于训练期价值估计，不参与部署。Critic 与 Actor 不共享可训练层、特征归一化器或
GRU，防止特权信息通过共享表示泄漏到部署策略。该结构属于典型的 asymmetric actor-critic：
Actor 使用可部署观测，Critic 使用仿真特权状态帮助降低价值估计难度。

Critic 输入固定为 65 维。基础 57 维由局部位置 3 维、六维旋转表示 6 维、线速度 3 维、
角速度 3 维、上一实际动作 7 维、接触标志与强度 2 维、胃壁法向与有效标志 4 维、可达与
原始累计覆盖 2 维，以及 `3 × 3 × 3` 面积加权覆盖网格 27 维组成。

覆盖网格在固定胃模型坐标系的包围体内沿三个轴各分三格。每格保存该空间单元中可达表面的
面积加权累计覆盖比例；不存在可达表面的空格定义为零。网格只供 Critic 使用，不进入 Actor，
也不替代正式精确覆盖指标。

其余 8 维由归一化剩余回合时间 1 维和恢复状态机 7 维组成。恢复状态机包括四阶段 one-hot、
当前停滞窗口进度、历史最大逃离进度和恢复计时器。时间输入用于正确表达固定 120 秒有限时域
任务，避免同一物理状态在不同剩余时间下被迫共享相同价值。

Critic 使用独立前馈 MLP `65 → 256 → 256 → 256 → 1`，隐藏层激活为 ELU。连续特权字段
使用只由训练数据更新的 running normalization；验证时冻结统计量，测试时不调用 Critic。

## 奖励与持续停滞恢复

正常覆盖奖励为 `100 ΔC_t`，其中 `ΔC_t` 是本动作边界新增的可达面积覆盖比例，`C_0` 只
初始化累计覆盖而不产生奖励。普通碰撞、受阻、短时静止、重复观察、HOLD、较大力度和单步
零新增覆盖均不直接处罚。

持续停滞使用最近 5 秒窗口判定。仅当窗口内最大位置位移不超过 1 mm、最大方向姿态变化不
超过 5 度且可达覆盖增量不超过 0.1 个百分点时，状态机才从正常阶段进入逃离阶段。停滞不
终止回合，也不清空 GRU。

进入逃离阶段时冻结位置与姿态锚点。位置相对锚点达到 3 mm 或方向姿态相对锚点达到 15 度
即满足物理逃离阈值；满足后进入最长 2 秒的等待覆盖阶段。只有等待期间新增可达覆盖至少
0.1 个百分点，才产生一次覆盖恢复事件并返回正常阶段。

奖励固定为

$$
r_t = 100\Delta C_t
+ 0.1[e_t-e_{t-1}^{\max}]_+
- 0.002\mathbb{1}_{\mathrm{no\ progress}}
+ 0.2\mathbb{1}_{\mathrm{coverage\ resume}}.
$$

其中 `e_t` 是相对冻结锚点的归一化逃离进度，`e_{t-1}^{max}` 是当前动作前的历史最大进度；
历史最大值在发放新增进展奖励后更新，因此同一位移不能重复获奖。`no progress` 只在恢复状态机
已触发但本步没有刷新历史最大逃离进度时取一。逃离进展奖励最长持续 10 秒；达到时限或等待覆盖失败后进入锁定阶段，
在真正出现新覆盖前不再发放逃离进展奖励。覆盖恢复后状态机重新解锁。该机制不在 95% 覆盖
后关闭。

## 终止与 bootstrap

120 秒是任务定义的一部分，属于真正的有限时域终止。执行到第 1200 个动作后，终止状态的
下一价值固定为零，不进行 bootstrap。持续停滞、低覆盖和恢复失败均不是终止条件。

只有与任务语义无关的人工采样切分可以从 Critic 下一价值 bootstrap。非有限状态、求解器或
渲染器异常、RGB 生成失败和帧同步失败属于故障，必须停止相应运行并保留证据，不能转换成
负奖励样本或普通超时。

## Recurrent PPO 配置

训练并行数冻结为 12，每环境 rollout 长度为 64 个 10 Hz 步骤，即 6.4 秒。每次更新收集
768 个环境转移。序列 minibatch 必须保持每个环境内部的时间顺序，不得把 64 个时间点独立
打乱；环境 reset 后的填充位置使用有效掩码，损失与优势归一化只统计有效位置。

PPO 配置固定为 `num_learning_epochs=5`、`num_mini_batches=4`、`clip_param=0.2`、
`use_clipped_value_loss=true`、`value_loss_coef=1.0`、初始学习率 `3e-4`、自适应学习率调度、
目标 KL `0.01`、最大梯度范数 `1.0`、`gamma=0.999`、`lambda=0.95` 和
`entropy_coef=0.005`。冻结 ResNet18 不进入优化器。

## 初始化

ResNet18 只加载指定预训练权重。新增视觉投影、上一动作投影、融合层和 Critic 隐藏层使用
增益 `sqrt(2)` 的正交初始化并将偏置置零；Critic 输出层使用增益 `1.0` 的正交初始化和零
偏置。GRU 循环权重使用正交初始化，输入权重使用 Xavier 初始化，全部偏置置零，初始隐状态
固定为零。

模式输出层使用增益 `0.01` 的正交初始化和零偏置，使初始六模式接近均匀分布。Beta 原始参数
输出层同样使用增益 `0.01` 的正交初始化，两个浓度偏置均设为
`log(exp(1)-1)`，从而在零输入附近满足 `1 + softplus(bias) = 2`，使五个力度分布接近
`Beta(2,2)`。

每次运行必须保存完整配置、代码提交、训练种子、模型参数量、可训练参数清单与冻结参数清单。
启动检查必须证明 ResNet18 不在优化器内、BatchNorm 不更新、十二个 GRU 隐状态独立，且
Actor 输入接口不存在任何特权字段。

检查点只在 PPO 更新与 rollout 边界保存。它包含可训练 Actor、Critic、优化器、自适应学习率
状态、Critic 归一化统计、更新编号、累计环境步数、训练随机数状态和配置哈希。开发阶段每
50 次更新保存滚动检查点，并永久保留第 250、500、750 和 1000 次更新的验证检查点。

本任务采用 rollout 更新边界恢复，不声称逐位复现未中断轨迹。恢复时加载上述训练状态，统一 reset
十二个环境、清空相应 GRU 隐状态和上一动作，从新的 rollout 边界继续累计更新数与环境步数。
报告必须记录恢复检查点哈希、恢复更新编号和额外 reset 次数。Gate 4 使用短时训练工件主动
验证一次该恢复流程；完整开发种子只有发生真实外部中断时才允许恢复。

进程退出或临时设备故障等外部中断可以从最后有效检查点恢复。若异常来自代码、奖励、非有限
训练量或超参数，则该次运行无效，修复后必须使用同一种子从第零次更新重新开始，不能从异常前
检查点续跑并把结果声明为完整开发实验。

## 脱离 Codex 的训练监督入口

实现必须新增一个位于 `scripts/stomach_coverage/` 的 TASK-010 训练监督脚本。该脚本以 Python
标准库实现 `start`、`status` 和 `resume` 三个公开入口，并以内部 worker 模式运行实际训练
子进程。`start` 创建唯一运行目录后，以独立进程会话启动 worker，打印运行目录与 PID 并立即
返回；Codex 进程、终端或 SSH 会话退出不得终止训练。`status` 只读取记录文件并报告当前状态，
不得附着到训练进程或改变训练状态；若 PID 不存在或心跳过期，应明确报告陈旧状态而不是仍称为
正常运行。`resume` 必须显式指定检查点，为恢复段创建新的唯一运行目录，并在清单中记录父运行
ID、检查点路径及 SHA-256，不得覆盖原运行目录。

监督脚本必须在训练开始前写入 `launch_manifest.json`，至少包含完整命令、启动时间、主机身份、
PID、Git 提交与工作区状态、配置文件及哈希、种子、环境数、计划更新数、Python、PyTorch、
Isaac Lab、驱动与 GPU 信息。配置或 Git 状态与启动时记录不一致时必须明确失败，不能静默使用
另一套参数。

worker 必须按真实发生顺序把训练子进程的标准输出和标准错误合并写入不缓冲的 `console.log`，
同时让训练循环继续写入权威的 `metrics.jsonl`。启动、预检查、每次检查点、每次验证、收到的
信号、Python 异常、非零退出和正常完成写入 `events.jsonl`。未捕获异常必须保留完整 traceback，
不能只保存最后一行错误。

监督脚本必须使用原子替换更新 `status.json`。状态至少区分 `starting`、`running`、`completed`、
`failed` 与 `interrupted`，并记录 worker PID、训练 PID、开始与结束时间、最后更新编号、最后
指标时间、最近检查点、退出码和错误摘要。运行期间每次 PPO 更新刷新状态；训练尚未产生新更新
时至少每 60 秒写入一次心跳，从而区分训练缓慢与进程已经消失。

运行目录必须位于 Linux 外部工件根目录，不能写入 Git。启动脚本必须检查目录可写、剩余空间
可用、同一运行 ID 没有活跃进程，并拒绝覆盖既有日志。完整 stdout、stderr、事件、指标和状态
记录默认保留；不得为了控制文件大小而丢弃错误行，也不得保存逐帧 RGB 或视频作为默认日志。

## 开发验证

后台开发种子在第 250、500、750 和 1000 次更新运行确定性验证。监控集合固定使用位姿库清单
`fixed_live_reload_pose_ids.validation` 已验收的 20 个 validation 位姿，不重新抽样，也不
加载测试 split。每个验证回合从零 GRU 隐状态开始，模式取最大概率动作，非 HOLD 力度取
Beta 均值；Critic 归一化统计冻结，验证不更新模型、优化器或任何训练统计。

开发种子完成后的独立运行记录必须同时给出训练真实吞吐、总运行时间、各验证节点的 `C_120` 与 `nAUC_120` 曲线、
最近 250 次与 500 次更新的增益、KL、分类熵、Beta 熵、价值解释方差、恢复与停滞统计、动作
分布、力度分布和峰值显存。开发种子不设置必须超过 TASK-009C 随机策略的论文门槛，但若没有
任何学习迹象、动作分布严重坍缩或训练量异常，不得直接进入正式训练。

## 验收门禁

Gate 1 是纯代码与配置门禁。它至少验证确定性图像裁剪与归一化、ResNet18 冻结、Actor 与
Critic 输入隔离、全部网络维度、六模式加条件 Beta 的概率与熵、HOLD 屏蔽、奖励状态机、
120 秒终止不 bootstrap、人工采样切分可 bootstrap、检查点字段和 split 隔离。

Gate 2 是十二环境 GPU 集成门禁。它连续采集多个完整 64 步序列，证明 RGB 与覆盖同帧、
每动作 24 个物理子步、逐环境覆盖与 GRU 状态不串扰、真实 reset 只清空对应隐状态、rollout
边界只截断梯度，以及所有观测、动作、奖励与价值有限。该门禁还必须证明 ResNet18 参数和
BatchNorm 统计量保持不变。

Gate 3 是短时学习门禁。它执行有限更新，证明 Actor、GRU、Critic 和优化器中的预期参数确实
变化，损失可以反向传播，动作概率与 Beta 浓度合法，日志能够重算，检查点能够按本文恢复并
继续增加累计更新与环境步数。该门禁只验证链路，不使用短时覆盖评价最终算法优劣。

Gate 4 是开发种子启动与日志门禁。它不执行完整 1000 次更新，而以独立冒烟种子 `991010`
后台运行 2 次 PPO 更新，冒烟配置把检查点间隔临时设为 1 且关闭验证；随后查询一次 `status`，
再从第 2 次更新的检查点恢复并运行 1 次更新。该冒烟配置只测试监督与恢复接口，不改变开发
种子 `991000` 的冻结配置。

Gate 4 还必须用独立测试夹具启动一个同时写入标准输出与标准错误、随后以退出码 23 失败的
短进程。门禁必须证明 `start` 返回后训练继续、运行目录与 PID 可定位、指标和心跳持续更新、
检查点可恢复，并且受控失败的完整 traceback、退出码 23 和 `failed` 状态均被保留。冒烟与
受控失败工件不得混入正式开发种子目录或后续学习曲线。

## 外部工件与返回报告

Git 只提交代码、测试、版本化配置、设计、实施计划、活动交接合同和返回报告。检查点、完整
日志、逐帧轨迹、RGB、截图和视频保存在 Linux 外部工件目录。返回报告必须记录每个关键工件
的绝对路径、字节数和 SHA-256。

Linux 返回报告必须包含任务编号、状态、基线提交、报告提交前 HEAD、完整分支名、环境身份、
实际执行命令与退出码、逐门禁直接观测结果、偏离合同的事项、未验证声明和工件路径。报告不得
把仓库配置或计划中的预期值写成已实测事实。

Gate 1 至 Gate 4 全部完成后，本次实现报告可以使用 `complete`，但必须把“完整 `991000`
训练尚未执行”列为明确的范围外未验证项。任何授权范围内仍未完成但已经取得有效进展的情况
使用 `partial`；架构或训练语义需要 Windows 决策时使用 `needs_decision`；外部依赖导致无法
继续时使用 `blocked`。本次报告不包含开发种子性能、三个正式种子的运行结果或论文级最终验收。

## 后续正式训练接口

完整开发种子由用户或独立 Linux 会话通过监督入口启动，无需 Codex 保持工作状态。训练结束后
再读取运行目录与自动日志形成开发种子报告。Windows 只允许根据该实测时间与曲线调整正式更新
总数、验证间隔和检查点间隔。
若修改网络、奖励、输入分辨率、十二环境并行数、64 步序列长度或 PPO 超参数，必须重新运行
开发种子。

后续正式基线使用 `991001`、`991002`、`991003` 三个独立种子，共享同一冻结配置，通过
validation split 选择检查点，最后在相同的 20 个冻结 test 状态上评价。该阶段另行制定执行
合同与最终验收，不属于本次 `TASK-010` 返回报告的交付范围。
