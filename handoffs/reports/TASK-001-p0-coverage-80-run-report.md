# TASK-001 P0 覆盖率80%自动运行报告

日期：2026-08-09

## 结论

已实现并实际运行“按动作边界循环调用，达到目标覆盖率后自动退出”的验证入口，且每次
运行都会生成覆盖PNG、掩码、轨迹、逐帧记录和统计JSON。但在不绕过既有动作、安全与
物理约束的前提下，本轮最高覆盖率为 **13.506%**，没有达到80%。因此本报告将结果标记
为`target_reached=false`，不把局部覆盖或多次独立重置的并集伪装成一次80%运行。

## 实现内容

- `teleop_atomic_stomach_coverage.py`新增：
  - `--target_coverage_percent`；
  - `--max_action_calls`；
  - `--auto_action_cycle`；
  - 达标自动退出、动作边界调度及`coverage_target_run.json`统计。
- 目标覆盖验证模式在执行器硬失败时保留安全制动，但禁止管理器抢先自动复位，以便外层
  记录准确失败码后退出；胃壁碰撞、传统碰撞和超时终止仍启用。
- 修复Ball/姿态原语把机械臂重力下垂误差固化为下一目标的问题：Ball原语现在持续保持
  上一次安全的六轴命令，只有滚动、靠近和远离原语显式改变机械臂目标。
- 增加跨管理器复位的单调总仿真时长记录；传感器时钟仍严格拒绝未声明的帧号倒退。

最高覆盖运行采用“10次`ROLL_POS`＋7次`AZIMUTH_POS`”分段折线探索；27次动作成功后，
第28次在磁场逆解奇异区触发`PLANNING_FAILED`，所需规划时长6.665 s超过单原语1.5 s
上限。单方向滚动在第18次触发`EXECUTION_TIMEOUT`。不安全的连续方位累加会在真实几何
仍未穿透时先触发5 mm胃壁安全缓冲`ENVIRONMENT_COLLISION`。

## 为什么继续盲循环不能达到80%

- 30次安全对称循环后覆盖停在9.022%，后续帧新增点趋近0。
- “滚动一次＋保持两次”30次后覆盖停在9.890%，最后两帧新增点为0。
- 相机覆盖只统计50 mm内且无遮挡的胃壁顶点；当前胶囊在一次30动作试验中的活动范围仅
  约`7.3 × 9.7 × 0.9 mm`，无法观察整个胃腔。
- 现有11原语主要完成局部姿态变化；外磁体长距离移动时胶囊只产生毫米级滞后位移，随后
  机械臂先到达规划/跟踪边界。继续增加重复次数不会产生新的有效胃内导航区域。

## 验证

- 纯逻辑：动作层与覆盖测试`40 passed`。
- 胃部GPU集成：11个冻结动作`11/11 DONE`，覆盖记录12帧，`status=PASS`。
- 机械臂目标保持修复后，30动作运行中ASM自碰撞间隙稳定约9.996 mm，不再因重力误差
  每个动作逐步下沉。
